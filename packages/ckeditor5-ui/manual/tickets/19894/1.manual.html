UI balloons are hidden behind a native <dialog> #19894

A modal <dialog> opened with showModal() is rendered in the browser's top layer, and everything outside of it becomes inert. The editor's overlay layer (balloons, tooltips, dialogs) is mounted in document.body by default, so it renders behind the dialog and cannot be clicked. The ui.overlayContainer configuration lets the integrator mount the overlay layer inside the dialog instead.

Each button below opens the same modal dialog with a new editor, configured as follows:

  1. Default – no ui.overlayContainer. Reproduces the issue: select text, click the link, hover the toolbar buttons, or open Find & Replace – none of the floating UI is visible.
  2. The <dialog> element – ui.overlayContainer: dialogElement. The floating UI is visible and usable, but a modal dialog has overflow: auto by default, so floating UI close to the dialog's edges is clipped and the dialog becomes scrollable. Check the link in the last paragraph or the table cell properties of the last table row.
  3. A fixed layer inside the <dialog> – ui.overlayContainer set to a position: fixed element placed inside the dialog. The floating UI is visible, usable, and may extend beyond the dialog's edges.

In modes 2 and 3, check that all of the following show up above the dialog content and work:

  • the balloon toolbar (select text) and the block toolbar (the handle on the left),
  • the link balloon (click the link) and the link form,
  • the image toolbar and the table toolbar, including the table cell properties color pickers,
  • the mention list (type @),
  • the toolbar button tooltips,
  • the Find & Replace dialog, which must be draggable,
  • the drop target line while dragging the image between blocks, also with the page and the dialog content scrolled.

Also check that:

  • Pressing Esc while a balloon is focused closes only the balloon. The dialog stays open.
  • Pressing Esc in the editing area while the link balloon is shown (the caret in the link) closes only the balloon. The next press closes the dialog.
  • A balloon follows its target when the dialog content is scrolled.
  • Closing the dialog destroys the editor and leaves no .ck-body-wrapper behind, and the dialog can be opened again in another mode.
