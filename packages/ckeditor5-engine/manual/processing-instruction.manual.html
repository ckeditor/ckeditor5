Requirements

This test needs a browser that parses <?target data?> in HTML into processing instruction nodes. Engines without that support parse the same markup into comments, so nothing below will be visible – that is expected, not a failure. To check, run in the console: 

new DOMParser().parseFromString( '<body><?foo bar?></body>', 'text/html' ).body.firstChild.nodeType === 7

Loading

  1. The editor should load without any error in the console. This alone covers the original problem, where a processing instruction reached the converter and had no tagName.
  2. The first paragraph should show two yellow boxes, <?marker start?> and <?marker end?>, around the words "between the markers".
  3. The second paragraph should show <?if !supportLists?>, the third one <?endif?> with no data part.
  4. The output below should repeat the source markup, with the instructions in the same positions relative to the text.

Testing

  1. Type text before, between and after the boxes, then press Print data. The instructions should stay in place relative to the surrounding text.
  2. Place the caret right after a box and press Backspace. The whole instruction should be removed and should disappear from the output.
  3. Undo the removal. The instruction should come back with the same target and data.
  4. Select a range covering one box and some text, then type over it. Only that instruction should be gone from the output.
  5. Press Reset data at any point to load the source markup again.
  6. Apply bold to text spanning a box. The instruction should survive and stay in the output.

Known limitations of this demo:

  • The instruction is rendered as a plain UI element, not a widget, so it cannot be selected by clicking. This keeps the test free of a dependency on ckeditor5-widget.
  • Copying and pasting an instruction does not preserve it. The clipboard uses its own data processor instance, which still skips processing instructions.
  • Data containing > is not handled. A processing instruction ends at the first > and there is no escaping, so such data would not survive a round trip.
