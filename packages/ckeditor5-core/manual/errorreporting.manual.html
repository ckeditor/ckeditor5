Error reporting

Important: start the server with CK_DEBUG=false pnpm manual. With CK_DEBUG on — which is the default — every // @if CK_DEBUG // throw err; line becomes live code, which skips the wrapping in CKEditorError.rethrowUnexpectedError(). A plain error then stays a plain error on its way out, and the last case below behaves differently.

One onEditorError() callback is registered for the whole page. Every reported error is appended to the log at the bottom, together with the editor it was attributed to. Keep the browser console open — reporting does not swallow anything, so every error should appear there as well.

  1. Click Throw from a plugin under the first editor. One entry should appear in the log, naming editor 1. The error should also be in the console.
  2. Do the same under the second editor. One entry, naming editor 2. Both editors should still work — nothing restarts, so the content stays exactly as it was.
  3. Type something in both editors, then throw again. The content must not change and undo must still reach what you typed, because the editor is never rebuilt.
  4. Click Throw with no attribution. The error is thrown with null as its context, so nothing should appear in the log — but it must still be visible in the console. This is what "reporting only, nothing swallowed" means.
  5. Click Throw a plain error. It is not a CKEditorError, so nothing should appear in the log, and the console shows it as usual.
  6. Click Throw from a plugin under the third editor. It is expected to be named editor 1 rather than editor 3 — see the note below. When this starts naming editor 3, attribution no longer searches object graphs and this case can go.

Why the third editor is misattributed. Which editor an error belongs to is currently decided by walking both object graphs and looking for anything they have in common, and the first editor that matches wins.

Editors 1 and 3 both load the list feature. ListEditing passes one and the same module-level array to the schema of every editor that loads it (LIST_BASE_ATTRIBUTES), so those two have an object in common and an error from either of them looks like it belongs to editor 1. It takes two editors to show this: a feature loaded by a single editor shares nothing with anyone. Editor 2 does not load lists, which is why it is named correctly.
